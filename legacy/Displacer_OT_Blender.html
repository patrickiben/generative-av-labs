S3 Splat space — 2D → 3D OT displacement in 3D splats —

drag to orbit · t slider drives the migration

Both images are lifted to 3D Gaussian-splat clouds (x,y from the frame; z from a stated luminance heuristic — bright = near), then matched by sliced optimal transport (iterated 1D quantile matching along random 6D projections over position + color). The t slider is a literal McCann displacement interpolation in splat space: A's splats migrate along their transport vectors into B's cloud. A hand-built, model-free cousin of the splat-readout idea in the splat-JEPA grounding-head proposal — the lift here is a heuristic, not a learned geometric readout. Solo mode lifts a single image (or sound) into its own 3D cloud — the t slider becomes the 2D→3D extrusion (flat postcard → full relief; depth is the stated heuristic, not learned monodepth). Audio mode: the splat analogue is the Gabor atom — each sound decomposes (greedy matching pursuit on the STFT) into Gaussian time-frequency blobs (x=time, y=log-f, z=salience); the same sliced-OT migrates A's atoms into B's, and "play atoms" resynthesizes the morph from the atoms themselves (each atom a windowed sinusoid — sparse and airy, own clean phase, not the full sound). Exports: cloud .ply = plain XYZ+RGB — opens with correct colors in TouchDesigner (Point File In → GPU instancing → your projection rig), Blender, CloudCompare. splat .ply = 3DGS format for splat viewers (SuperSplat, PlayCanvas). macOS Preview shows both as flat squares — don't judge them there.

Parametric synesthesia — every correspondence is a stated, deterministic map with a named perceptual grounding (spectrogram convention, pitch-height, loudness–brightness, spectral color). A designed convention, not a learned embedding — no model. The transport is geometric (sliced-OT in the stated space), not semantic. Exports come from the raw displaced cloud, never the glow render.

08 What's exact vs. approximate read me

✅ Exact here

  • The 1D inverse-CDF map is the exact closed-form W₂ optimal-transport map (McCann displacement interpolation) for 1D distributions — a theorem, not an approximation.
  • Image: per-channel transport of A's value histogram toward B's, along the intensity axis. Mass migrates linearly (mean slides A→B).
  • Audio: per-STFT-frame transport of the magnitude spectrum along the frequency axis (energy moves to new bins, conserved per frame).
  • The crossfade baseline is the honest naive control — it sums the two distributions (ghosting), it doesn't move mass.

🧪 Approximate / not running

  • Image LUT/sliced modes recolor only (A keeps its geometry). The Spatial OT method moves the sampled pixel cloud exactly (W₂ on x,y,color); its flat image is an approximate splat reconstruction, and correspondence is geometric — not semantic/optical-flow. Compositing rule is stated & switchable (soft-nearest vs occlusion-blind mean) — per the splat-research finding that the compositing model can silently shape what a splat render appears to show. The S3 orbit view uses sorted painter's compositing; apparent coherence there comes from the lift, not recovered geometry. Splat size follows the research's attribution-ladder discipline: default = ONE per-point parameter (contrast-adaptive size); the global-size 'PointHead rung' is one click away for A/B.
  • Audio phase is reconstructed heuristically (dominant-source or phase-vocoder) — there is no exact phase for a transported magnitude, so transients can smear near t≈0.5. The magnitude transport is exact; the phase is the hard part.
  • Per-channel / per-frame 1D transport ≈ the full 2D Sinkhorn (joint color cloud / time-frequency) — the heavy version we deliberately don't run.
  • No learned model: it won't hallucinate a new in-between texture (that's diffusion/AudioLDM territory) — expect clean migration, not an invented hybrid.

// distributions p (from A) and q (from B), as normalized histograms → CDFs F_p, F_q
// the EXACT W2 optimal map: T(x) = Q_q(F_p(x))   where Q_q = inverse CDF of q
// McCann displacement interpolation at blend t:
T_t(x) = (1-t)*x + t * Q_q( F_p(x) )
// image: x = a pixel's channel value (axis = intensity)
// audio: x = a frequency bin position (axis = frequency), transporting magnitude mass
